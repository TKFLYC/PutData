## 一、摘要結論

**兩工具在本機實驗室完成 11 個案例(C1 拆為全量 / 增量,共 12 列):8 列通過、4 列因實驗室限制無法執行(非失敗)、0 列失敗,達可交付狀態;增量相關情境須在客戶環境補驗。**

- 驗證目標:確認 NimoShake `mchange_cast` 以 v2 規則檔將 **23 張表 / 43 個受治理欄位**(33 個 Int32、10 個 Int64)正確轉型,並確認 nimo-full-check 能證明「轉了、轉對、且規則全數命中」
- 驗證環境:DynamoDB Local → MongoDB(單機),合成資料 **1,380 筆**(23 表 × 60;含刻意植入的前導零、負零、超界、小數等拒轉反例)
- 核心證據:全量搬遷 exit 0、**2,580 個受治理值**逐值稽核 errors 0;校驗工具正反向各能抓到錯誤(exit 1);規則沒命中資料時升 exit 2 而非假 PASS
- 無法在本機驗證的:增量同步、shard 交接、checkpoint 續跑判定、指紋不符拒絕啟動(原因:DynamoDB Local 必須設 `source.endpoint_url`,產品在此設定下只允許 `sync_mode = full`)

## 四、關鍵行為的實測證據(本機實驗室合成資料,未驗客戶環境)

### 4.1 啟動摘要三行(C1 實收;`database` 與 `rules_sha256` 為實驗室值,客戶環境不同)

```text
[INFO] (nimo-shake/protocol.InitTypeRules:42) schema=v2 semantics=collection_scoped config_id=opapp.type-conversion config_version=2026-09-11.1 database=<conf 的 id> collections=23 governed_collections=20 preserve_only=3 rules=43 rules_sha256=<規則檔 SHA256>
[INFO] (nimo-shake/protocol.InitTypeRules:42) source _id fields=0; convert._id has no effect
[INFO] (nimo-shake/protocol.InitTypeRules:42) source_id_basis=declared_mapping convert_id=pre
```

### 4.2 目的端逐值稽核(C1)

```json
"counters": {
  "documents": 1380,
  "keys_checked": 1380,
  "governed_values_checked": 2580,
  "converted_values": 2365,
  "preserved_exceptions": 129,
  "null_or_missing": 86,
  "preserve_only_values": 360
},
"errors": []
```

129 個拒轉保留值全部是刻意植入的反例(前導零、負零、非數字字串、小數、超界、型別不符),工具逐筆保留原值並在校驗端列為 `SOURCE_UNCASTABLE` 帶 `reason`。

### 4.3 遷移端 preflight 拒絕字面(C4)

```text
selected collections do not match contract: missing=[user_def_payment] extra=[]            ← 少一張
selected collections do not match contract: missing=[] extra=[<規則檔未宣告的表名>]         ← 多一張
selected collections do not match contract: missing=[user_def_payment] extra=[user_def_paymant]   ← 拼錯
```

三案都在建立 checkpoint 與寫入目的端之前停止。

### 4.4 校驗端 exit code 實收對照

| 情境 | 實收 exit | outcome |
|---|---|---|
| 乾淨資料 + 合成拒轉反例(C8 forward / both)| 3 / 3 | `PASS_WITH_EXCEPTIONS`,43 列 coverage 完整 |
| 目的端型別被破壞(C9 forward)| 1 | `FAIL` |
| 以未轉型資料驗(C9 reverse)| 1 | `FAIL` |
| 規則全數 `zero_hits`(C10)| 2 | `EXECUTION_ERROR`,989 列 |
| `--resume` 續跑(C7)| 3 | `coverage_complete = false`,不作完整性證明 |

「沒有可轉型的觀察值」規則:原結果為 FAIL 或 PASS_WITH_EXCEPTIONS 時保留原結果;原為 PASS 時升 exit 2(該規則未被驗證過)。此行為以單元測試驗證(六格情境全數符合)。

## 五、報告判讀指南

| exit | 意義 | 建議動作 |
|---|---|---|
| 0 | `PASS`,全數通過且規則覆蓋完整 | 無 |
| 1 | `FAIL`,存在轉型錯誤或兩端資料不一致 | 檢視 diff 行(主鍵 / 欄位路徑 / 兩端值 / 分類 / reason)|
| 2 | `EXECUTION_ERROR`,執行障礙、沒跑完、或規則覆蓋不完整 | `checked` 不可對帳;排除後不帶 resume 全量重跑 |
| 3 | `PASS_WITH_EXCEPTIONS`,通過但來源有不可轉資料 | 逐筆檢視 `SOURCE_UNCASTABLE` 的 `reason`,逐案判定後才能結案 |

完整判讀(四欄全量證明、`rule-coverage.json` header 與 43 列)見 `docs/部署與使用說明.md` 第六節。

## 六、交付物

- `nimo-shake.linux` / `nimo-full-check.linux`:linux/amd64,Go 1.20.14,CGO 啟用,**動態連結**(客戶主機需相容 glibc);`-version` / `--version` 可查契約與源碼指紋
- `type_rules_opapp.json`:23 表 / 43 條規則(兩工具共用);`scope.database` 出廠為佔位,須改成 conf 的 `id`
- 檔案 SHA256 見 `SHA256SUMS`

## 七、已知限制

- 指紋核對只保護「從 `incr_sync` 續跑」;改規則後以 full 重跑不會被擋,會依 `target.db.exist` 重建
- `checkpoint.type = file` 時落檔位置由 `checkpoint.db` 決定,`checkpoint.address` 被忽略
- 任何 `--resume` 的校驗都不作完整性證明
- 校驗端白名單多寫一個 DynamoDB 不存在的表名不擋(仍涵蓋宣告的 23 表);少一張 / 拼錯 / 多列一張存在但未宣告的表會擋
- Scan 非時間點快照;搬遷仍在寫入時執行校驗會有暫態差異(以 `--convergeRetries` 收斂)
- `-m both` 與 checkpoint / 分段互斥
